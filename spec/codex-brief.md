# Codex 任务书：云墟仙途 Clean-Room 重建

## 项目
从零重建修仙文字冒险游戏「云墟仙途」(Yunxu Xiantu)。原版是迭代 8 轮拼出来的，结构混乱；这次按全部要求从头设计、从头实现。工作目录即本目录 `~/workspace/yunxu-rebuild/`。**不要动线上空间**（不碰 `~/workspace/ts-spaces/`、不用 artifact 工具、不读线上空间源码）。

## 先读的规格（都在 `spec/` 里）
- `spec/design-doc.md` —— 完整设计文档与需求时间线（主规格）
- `spec/architecture.md` —— 可观察架构：22 个对外接口、数据模型、9 大系统
- `spec/save-export.json` —— 线上存档（杨柳青：混沌灵根、青云宗外门、炼气 3 层、修为 33、灵石 78、5 段故事），重建版必须能导入它、无缝续玩
- `spec/standing-requirements.md` —— 用户的长期要求
- 另读 `~/workspace/yunxu-xian-tu-package/conversations/` 里的对话原文，了解用户原话里的要求。

## 工作流（必须按这个来）
用已装好的 Codex 工作流：superpowers（brainstorm → plan → TDD → implement → verify）、mattpocock-skills、最后做 Trail of Bits 安全审查。
分阶段交付，每阶段结束把成果写进文件再停，不要一次写完不存盘：

- **Phase 1 — 规划**：写 `PLAN.md`：干净架构（server + client 分工、数据模型、接口清单对齐原版 22 个接口、存档迁移方案、技术选型：Node 24 + 哪个 web 框架/数据库/测试框架，并说明理由）。先规划，不写业务代码。
- **Phase 2 — 服务器核心**：实现规则引擎（数值结算与 AI 叙事分离：服务器按固定规则结算一切数值，叙事只走一个明确的 `narrate()` 适配器边界）。包括：角色创建（家世、灵根自选、混沌灵根置顶 ×2 修炼、+15% 突破）、境界（4 重至元婴，炼气 9 层按修为推导）、章节锁（每章 3 次本章历练 + 硬门槛，本章面板）、行动点/精力与天数、战斗（回合制）、突破、任务、经济（灵石/炼丹/买卖/装备强化）、好感（9 位 NPC，女主际遇 3 段、门槛 25/55）、门派贡献晋升、探索抉择事件（50%）、图鉴 3 类、前世录/轮回、成就 18 个、自选目标 5 类（奖励修为+20/灵石+25）。TDD：先写测试再实现。
- **Phase 3 — 客户端**：iOS 玻璃拟态、手机优先 UI；故事页（打字机按总长定速整段约 2.2 秒、自由行动面板、换一批、本章面板、目标进度条）、聊天页（💡 提示按钮、3–4 条候选台词）、任务堂、问天铺、背包、图鉴、成就。预生成建议走质量规则：像「在耳边出主意的伙伴」，三种心思混着来（能做的事、想说的话、带情绪的念头），长短不一，至少两条点名结尾出现过的具体人和物，上一批喂回去防重复；聊天台词用真人聊天语气，短促反问可，咬住对方原话不重复，无客套废话。篇幅分档：日常 300–420 字，主线/任务/际遇/突破/结局 650–900 字。第一人称现代爽文。
- **Phase 4 — 存档迁移 + 验证**：写迁移脚本 `src/server/migrate.ts`（或等价物），读 `spec/save-export.json` 导入并验证杨柳青完整无损（名字、灵根、宗门、境界、修为、灵石、5 段故事、成就、章节进度全部对上）。跑全部测试，本地起服务实测关键链路（建角 → 打坐 → 主线锁拦截 → 目标领取 → 战斗一回合 → 迁移导入）。把真实结果（通过/失败）写进 `REBUILD-REPORT.md`，不要编造。

## 用户补充的四条硬要求（2026-11-12，与原任务同等重要，验收时逐条核对）

1. **一定要改良，不是 1:1 复刻**：在原版基础上真正做得更好——结构更顺、成长感更强、体验更完整。不能只把旧东西原样抄一遍。PLAN.md 里必须有一节写清楚「比原版好在哪里」（每一点改良写明改了什么、为什么更好）。
2. **原本的所有故事性一定不能丢**：现有全部故事内容必须保留并迁移，一段都不能少——杨柳青已有的 5 段故事（《临渊测灵》《云墟山下》《混沌何解》《偏要五路都走》《青云入门》）、8 章主线剧情、9 位故人的人设与关系线、6 位女主的红颜际遇剧情（每人初遇→交心→情缘深种）、18 个成就与前世录设定。新架构要装得下这些内容，而不是为了干净砍掉它们。PLAN.md 里列一份内容迁移清单逐项打勾；迁移脚本必须原样导入 5 段故事正文（包括开篇《临渊测灵》的第三人称原文）。
3. **前端 UI 再往上做一档**：在现有 iOS 玻璃拟态、手机优先的基础上加强——视觉层次、动效、信息排布、操作手感都要更精致、更顺手。PLAN.md 里写 UI 升级方案（具体到：层级、动效、排布、手感各怎么加强）。
4. **可以添加便利功能**：允许自行加入实用的便利功能（例如一键继续、剧情回顾/前情提要、快捷操作入口等，按游戏需要自行取舍），但每个新增功能都要写进 REBUILD-REPORT.md，说明它是什么、为什么加。
